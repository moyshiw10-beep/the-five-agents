# פריסה — מצב נתמך ומה חסר

המסמך הזה מתאר איך להפעיל את המערכת. הוא לא מפעיל שרת ציבורי, לא פותח חשבון, ולא משנה נתוני ייצור.

## מה קיים במאגר

אין בריפו הזה `Dockerfile`, `vercel.json`, `render.yaml`, `fly.toml`, או workflow של פריסה. אין חשבון אירוח מחובר שאפשר להשתמש בו מחדש. הדוגמאות למטה הן צורת ההרצה הנתמכת, לא משאבים שכבר נפתחו.

## צורת ההרצה הנתמכת

תהליך Node ארוך טווח, לא פונקציית serverless, יחד עם PostgreSQL.

סנכרון לוגליג האמיתי מפעיל את Playwright ואת Chromium. זה לא מתאים ל-Vercel או לכל סביבת serverless עם מגבלת זמן וגודל. אם הסנכרון רץ על אותו שרת כמו האתר, לשרת צריכה להיות אפשרות להתקין את Chromium (`npx playwright install --with-deps chromium`). עד שהסלקטורים ב-`src/lib/logliga/selectors.ts` מאומתים מול האתר, משאירים `LOGLIGA_USE_MOCK=true` ולא מכניסים סיסמת לוגליג.

PostgreSQL נדרש. `prisma/migrations/20260914181032_init` הוא המיגרציה הקיימת, ומחילים אותה עם `npx prisma migrate deploy`.

## משתני סביבה

להעתיק מ-`.env.example` אל סביבת האירוח, בלי לשמור את הערכים בגיט:

- `DATABASE_URL` — מסד PostgreSQL ריק ששייך למערכת הזו.
- `NEXTAUTH_URL` — כתובת האתר המלאה, כולל `https://`.
- `NEXTAUTH_SECRET` — מחרוזת אקראית ארוכה.
- `CRON_SECRET` — מחרוזת אקראית נפרדת, אם מפעילים את נתיבי ה-cron.
- `SEED_PASSWORD` — רק לזריעה הראשונה, 12 תווים לפחות, ולא סיסמה משותפת.
- `SMTP_*` — רק אם שולחים דוחות. בלי זה הדוחות נכשלים בשליחה, והאתר עצמו עולה.
- `LOGLIGA_USE_MOCK=true` עד שיש אימות סלקטורים וסיסמה אמיתית שנמסרת מחוץ לגיט.

## צעדים אחרי שיש שרת ומסד

```bash
cd hall-management
npm ci
npx prisma migrate deploy
npx prisma generate
npm run build
SEED_PASSWORD='…' npm run prisma:seed
npm run start
```

`prisma:seed` יוצר משתמשי דמו סינתטיים ואינו מדפיס את הסיסמה. אין להריץ אותו על מסד עם נתונים אמיתיים.

אחרי שהחשבון הראשון עובד, יוצרים משתמשים אמיתיים מתוך המערכת ומוחקים את משתמשי הדוגמה.

## מה נדרש מהבעלים כדי שתהיה כתובת אתר

1. לבחור מארח עם תהליך Node קבוע ומסד PostgreSQL. לא להסתמך על Vercel לסנכרון Playwright.
2. ליצור את המסד ואת המשתנים למעלה בחשבון הקיים שלהם. הפעולה הזו לא בוצעה מכאן, כי אין חשבון אירוח במאגר ואסור לפתוח משאב בתשלום.
3. להריץ את הפקודות למעלה, או לחבר אותן ל-build של המארח.
4. לפתוח את `NEXTAUTH_URL` רק אחרי שהסודות הוגדרו. בלי `NEXTAUTH_SECRET` ו-`DATABASE_URL` אין אתר עובד.

אין כתובת ציבורית בשלב הזה, ואין תצוגה מקדימה פרטית שאומתה כמבודדת מחוץ למכונה הזו.
